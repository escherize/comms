# ADR-0014: read sessions ride on enrolment

**Status:** accepted, 2026-08-09. Narrows ADR-0012's "reads are open; the network is the perimeter" and DEPLOY's "the binary will not do it for you". **Narrowed in turn by ADR-0015:** the opt-in `--read-auth` flag became always-on (there is no open-read mode), and "any enrolled seat reads everything" became "reads the rooms it is a member of".

Reads were open by design: posting carries an ed25519 signature, reading is for whoever can reach the port, and the deployment question was "what is the perimeter", answered with a tailnet or a proxy. The first real deployment answered it differently: `fly launch` hands out a public hostname, the guide's safe options both cost more friction than the unsafe one, and the room was world-readable within the hour. When the safe path is the high-friction path, the perimeter argument is an argument with how people behave, and it loses.

So the binary now offers read auth — but it invents no identity to do it. Every seat already holds an enrolled keypair: the CLI's in `~/.config/comms/keys`, the browser's non-extractable in IndexedDB. With `--read-auth` on, a read needs a session, and a session is minted by signing a server nonce with an enrolled key — the same key store, the same revocation and compromise checks as posting. "May read" and "may post" are one enrolment, not two systems. The challenge is single-use and short-lived, so a captured signature names a nonce that no longer exists; the session is a bearer token in a cookie (browser) or an `X-Session` header (CLI), and the CLI establishes one transparently on the first 401, so a hub turning the flag on breaks no workflow.

Three trust boundaries stay exactly where they were. Loopback bypasses the gate, as it may mint invites: being on the box is holding the database — which means a proxy dialling 127.0.0.1, like `tailscale serve`, waves everyone through, correct only because a tailnet is already a perimeter. Self-authenticating routes (`/commands`, `/keys`, `/escalate`, `/invite`, the session pair) stay open: each re-proves identity per request, which is stronger than a session, and gating enrolment behind a session would deadlock the first visit. And the flag defaults to off: on a private network the perimeter is still the auth, and the sessions, the unlock page, and the client machinery all stay out of the way.

Sessions live in memory. The log is the only state worth keeping; a hub restart forgets every session and costs each client one signature to re-establish — the stale-token path is tested, not hoped. What this deliberately is not: per-request read signatures (heavy for SSE and useless while the body is a bearer channel anyway), an account system, or an authorization model — any enrolled seat reads everything, which is what a room is. The threat it addresses is the anonymous internet reading a public hostname, not an enrolled colleague; an enrolled seat's token leaking still exposes reads until expiry, thirty days, chosen over re-signing friction with eyes open.

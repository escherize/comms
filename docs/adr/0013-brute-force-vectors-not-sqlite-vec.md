# ADR-0013: the semantic lane is brute-force cosine in Go, not sqlite-vec

**Status:** accepted, 2026-08-07. Supersedes ARCHITECTURE's naming of sqlite-vec.

ARCHITECTURE names sqlite-vec for the vector lane and it was never reachable: ADR-0009 chooses `modernc.org/sqlite`, a pure-Go transpilation of SQLite with no C ABI, and sqlite-vec is a loadable C extension. The two decisions were made in different passes and neither noticed the other. The real choice was between giving up the pure-Go build — which is what makes this one static binary with no cgo toolchain, on any machine a colleague lends — and doing the arithmetic ourselves. We kept the build.

Vectors are float32 blobs in a `vector` table keyed by seq; `NearestVectors` scans a room and scores cosine similarity in Go. This is a linear scan and it is not the expensive part at this size: a room of 10⁵ events at 384 dimensions is 150MB read once and scored in tens of milliseconds, while the embedding call that produced the *query* vector costs more than comparing it against everything. The lane is also filtered by room before scoring, and rooms are the unit teams actually work in. When a room grows past the point where that stops holding, the fix is an approximate index, not a different SQLite driver — and the seam that would carry it (`Embedder`, `NearestVectors`) is already the only thing the rest of the system sees.

Two properties fall out of doing it in Go rather than in an extension. The model name is stored beside every vector and rows from a different model are skipped rather than scored, because a cosine computed across two embedding spaces is a number with no meaning and looks exactly like a real one. And there is a similarity floor: without it "nearest" means "every event in the room, ordered", so an unrelated entry comes back ranked third at similarity zero — the lane asserting a relationship that does not exist, which a reader cannot distinguish from a weak but real match. Live verification produced exactly that row before the floor was added.

What we give up: an ANN index's sublinear query, and any hope of pushing the scan into SQLite's query planner. What we keep: one binary, no cgo, no extension to load at the right version on every machine in a pooled-compute fleet, and an embedder seam whose properties — watermark, retries, dead-letter, fusion — are testable against a fake that returns arithmetic.
